# 교통문화연수원 태양광 점검·유지보수 서비스

교통문화연수원의 태양광 설비를 대상으로 발전 현황 확인, 드론 촬영 경로 생성, 영상 기반 패널 점검, 유지보수 업무 관리를 한 화면에서 수행하는 웹 서비스입니다. 사용자 역할을 선택해 화면에 접속하며, 홈페이지 우측 하단의 **AI 도우미**로 연결된 문서에 대해 질문할 수 있습니다.

현재는 **교통문화연수원 1개 발전소를 대상으로 하는 시연 서비스**입니다. 전사 이미지의 패널 열 탐지와 업로드 영상 분석은 실제 모델로 실행합니다. 발전·기상 수치와 업무 화면에는 시뮬레이션 자료가 포함되어 있으며, 드론 경로 전송은 완료 알림을 표시하는 방식으로 구현되어 있습니다.

## 주요 기능

| 기능 | 설명 |
| --- | --- |
| 발전 현황 | 발전출력·발전량·발전전력 추이, 기상·모듈 현황, 발전소별 상태를 확인합니다. 현재 표시 수치는 시뮬레이션 자료입니다. |
| 드론 점검 | 전사 이미지로 패널 열을 탐지하고 촬영 경로를 생성한 뒤, 촬영 영상을 업로드해 분석합니다. |
| 패널 상태 | 배치도와 목록에서 외관 판정, 검토·조치 및 이력을 확인합니다. |
| 유지보수 관리 | 점검 요청, 일정·배정, 견적, 작업 보고와 검수 등의 업무 흐름을 역할별로 제공합니다. |
| 알림·업무함 | 담당 업무와 알림을 확인하고 관련 작업 화면으로 이동합니다. |
| AI 도우미 | AgentStream 챗봇과 연결된 문서를 활용해 질문에 답변합니다. 답변 스트리밍, 생성 중지, 새 대화를 지원합니다. |
| 화면 설정 | 다크·라이트 테마를 선택하고 모바일에서도 화면을 이용할 수 있습니다. |

## 사용자 역할

첫 화면에서 접속할 역할을 선택합니다. 역할별로 메뉴와 수행할 수 있는 작업이 달라집니다.

| 역할 | 주요 이용 화면 |
| --- | --- |
| 발전소 사용자 | 발전 현황, 내 점검, 승인할 일, 작업 이력 |
| 지역관리자 | 지역 현황, 요청·응답 확인 |
| 드론 수행자 | 배정 점검, 촬영 자료 등록·분석, 패널 상태 열람 |
| 정비·세척 업체 | 요청·견적, 작업 수행·보고 |
| 마스터 | 전체 업무 확인, 일정·배정, 작업·검수, 조직·권한 관리 |

역할 선택은 시연을 위한 기능이며 실제 계정 로그인이나 서버 권한 인증을 대신하지 않습니다. 발전소 조회 범위는 모든 역할에서 교통문화연수원으로 제한됩니다.

## 드론 점검 사용 방법

**드론 수행자 → 배정 점검 → `INS-2026-031`** 순서로 접속합니다. 해당 점검에 새로 들어가거나 페이지를 새로고침하면 이미지·영상·결과는 업로드 전 상태로 시작합니다. 같은 점검 화면 안에서 단계만 전환하면 진행 중인 입력과 분석 상태를 유지합니다.

### 1. 전사 촬영 및 경로 생성

1. 고도에서 촬영한 태양광 단지의 전사 이미지를 업로드합니다.
2. **패널 탐지 실행**을 누르면 `solar_row.pt` 모델이 회전된 패널 열 박스인 OBB를 탐지합니다.
3. 박스의 긴 축 각도와 연장선상의 위치를 비교해 같은 열의 분리된 박스들을 통합합니다. 각도가 같더라도 옆에 나란히 놓인 다른 열은 구분합니다.
4. 통합된 열의 양 끝에 번호를 매기고, 인접 열마다 진행 방향을 반대로 연결해 지그재그 경로를 생성합니다.
5. **전송**을 누르면 비행 경로를 전송했다는 확인 알림이 표시됩니다.

이미지는 JPEG·PNG·WebP, 최대 8MB·3천만 화소를 지원합니다. 경로 좌표는 업로드 이미지의 픽셀 좌표이며, 현재 실제 드론 통신·GPS 좌표 변환·기체 자동 비행 명령은 실행하지 않습니다.

### 2. 촬영 데이터 업로드 및 분석

촬영한 영상을 선택하고 **영상 분석**을 누릅니다. 업로드 진행률과 분석 상태를 확인할 수 있으며, 분석을 마치면 **결과 보기**로 이동합니다.

기존 분석 엔진은 5프레임 간격으로 영상을 처리합니다. 패널 검출·영역 추출·외관 분류·결함 확인을 수행하고, 동일 패널의 추적 결과와 판정 횟수를 누적합니다. 정상·오염·육안상 파손·미판정 등의 상태와 근거 이미지를 생성합니다.

영상은 MP4·MOV·AVI·MKV·WebM·M4V 확장자, 최대 500MB·10분을 지원합니다. 실제 처리 가능 여부는 영상 코덱과 파일 상태에도 영향을 받습니다. 서버에서는 한 번에 하나의 영상 분석 작업을 수행합니다.

### 3. 결과 확인

이번에 업로드한 영상의 분석이 완료되어야 결과 화면이 표시됩니다. 현재 `INS-2026-031`의 화면에는 **기존 `testload_1` 분석으로 만들어 둔 고정 가상지도**가 표시됩니다.

| 고정 지도 항목 | 수량 |
| --- | ---: |
| 전체 패널 | 155개 |
| 외관 정상 | 45개 |
| 오염 | 99개 |
| 육안상 파손 | 0개 |
| 미탐지 | 11개 |

새로 영상을 분석하더라도 이 결과 화면의 배치·판정·상세 근거는 고정본을 사용합니다. 새 영상의 실제 분석 결과는 서버의 별도 작업 기록으로 저장되며 고정 지도를 덮어쓰지 않습니다.

지도에서 패널을 선택하면 오른쪽 요약 영역이 **패널 상세정보**로 바뀝니다. 원본 위치 이미지, 패널 이미지, 위치·판정·오염 종류·누적 판정·관측 트랙·프레임 정보를 확인할 수 있습니다. **결과 요약** 버튼으로 전체 통계로 돌아가며, 지도는 확대·축소·이동을 지원합니다. 관측 근거가 없는 미탐지 패널에는 임의의 이미지를 표시하지 않습니다.

## AI 도우미 사용 방법

홈페이지 우측 하단의 **AI 도우미** 버튼을 누르면 챗봇 위젯이 열립니다.

- Enter로 질문을 전송하고 Shift+Enter로 줄바꿈합니다.
- 답변은 생성되는 순서대로 표시되며, 완료·실패·중지 상태를 구분합니다.
- 생성 중에는 중지 버튼을 사용할 수 있고, 실패·중지 시 이미 받은 답변은 유지됩니다.
- 위젯을 닫았다 다시 열어도 현재 페이지의 대화는 유지됩니다. **새 대화** 또는 페이지 새로고침으로 초기화합니다.

챗봇은 AgentStream에 설정된 모델·프롬프트·RAG 문서를 사용합니다. 앱에서 별도 시스템 프롬프트를 덧붙이거나 화면의 전체 발전·점검 데이터를 자동 전송하지 않습니다. 질문과 답변은 AgentStream의 이력 정책에 따라 저장될 수 있습니다.

## 기술 구성

| 구분 | 구성 |
| --- | --- |
| 프런트엔드 | React, JavaScript, HTML, CSS, SVG 기반 지도·경로 표시 |
| 백엔드 | Python, FastAPI, Uvicorn |
| 이미지·영상 분석 | PyTorch, Ultralytics YOLO, OpenCV, Pillow, FFmpeg |
| 챗봇 연동 | HTTPX 기반 서버 중계, NDJSON 스트리밍 |
| 데이터 보관 | 분석 작업별 JSON·영상·이미지 파일, 고정 지도 스냅샷, 브라우저 IndexedDB·LocalStorage |
| 실행 포트 | `8501` |

화면은 React와 스타일이 포함된 `index.html`로 제공됩니다. 별도 Node.js 개발 서버 없이 FastAPI에서 화면과 분석 API를 함께 서비스합니다.

### 사용 모델

모델 파일은 현재 환경의 `/data/panel_models`에 준비되어 있습니다.

| 파일 | 용도 |
| --- | --- |
| `solar_row.pt` | 단일 클래스 OBB 기반 패널 열 탐지 |
| `panel_obb.pt` | 영상 내 개별 패널 OBB 검출 |
| `panel_seg.pt` | 패널 영역 추출 |
| `panel_class_cls.pt` | 패널 외관 분류 |
| `panel_crack_seg.pt` | 균열 영역 확인 |
| `panel_dirty_class_obb.pt` | 오염 세부 유형 검출 |

영상 분석 모델 경로는 `PANEL_MODEL_DIR` 환경변수로 변경할 수 있습니다. 열 탐지 모델은 현재 `app.py`에 지정된 `/data/panel_models/solar_row.pt`를 사용합니다. CUDA를 사용할 수 있으면 GPU로 추론하고, 그렇지 않으면 CPU를 사용합니다.

## 실행 및 설정

현재 서버에는 `.venv`와 분석 모델이 준비되어 있습니다. 새 환경에서는 Python 실행 환경과 위 기술 구성의 라이브러리, 모델 파일 및 필요한 원본 분석 자료를 별도로 준비해야 합니다.

저장소 루트에서 다음과 같이 실행합니다.

```bash
cd hackathon/intro
.venv/bin/python server.py
```

서버는 `0.0.0.0:8501`에서 실행됩니다. 같은 환경에서는 `http://localhost:8501`로 접속하고, 현재 배포 환경에서는 상단의 서비스 주소로 접속합니다. 별도 분석 작업 화면은 `/analysis` 경로입니다.

### 챗봇 환경변수

`.env.example`을 `.env`로 복사하고 API 키를 입력하거나, 동일한 이름의 서버 환경변수를 설정합니다. 환경변수가 `.env`보다 우선합니다.

```bash
cp .env.example .env
```

| 환경변수 | 설명 |
| --- | --- |
| `AGENTSTREAM_BASE_URL` | AgentStream API 기본 주소 |
| `AGENTSTREAM_CHATBOT_ID` | 연결할 챗봇 UUID |
| `AGENTSTREAM_API_KEY` | 해당 챗봇을 호출할 서버 전용 API 키 |

API 키는 브라우저로 전달하지 않으며 실제 `.env`는 Git에서 제외합니다. 요청은 브라우저 → `/api/chat/messages` → AgentStream `/open/v1` 순서로 전달합니다.

서버는 방문자별 HttpOnly 쿠키와 자체 대화 ID로 외부 세션을 구분합니다. 첫 질문으로 세션을 생성한 뒤 같은 질문을 메시지 API로 전송하고, 후속 질문은 동일한 세션을 사용합니다. `assistant.delta`의 텍스트만 표시하고 `turn.completed`를 받아야 완료로 처리합니다. 실패한 POST를 자동 재전송하지 않습니다.

방문자·대화 매핑은 서버 메모리에 보관하며 마지막 사용 후 최대 24시간 유지합니다. 서버 재시작 시에는 새 대화를 시작해야 합니다.

### 화면 수정 반영

`frontend/inspection_flow.*`, `frontend/chat_widget.*`, `frontend/site_config.js`, `frontend/sim.js`를 변경했다면 다음 명령으로 서비스 번들을 갱신합니다.

```bash
.venv/bin/python build_inspection_frontend.py
```

이 스크립트는 지정된 확장 파일을 기존 화면 번들에 반영합니다. 모든 JSX 파일을 변환하는 범용 React 빌드 도구는 아닙니다. 다른 JSX 화면을 수정할 때는 배포 HTML에 포함된 컴포넌트도 함께 갱신해야 합니다.

## 검증

```bash
.venv/bin/python -m unittest test_chat_service test_row_route test_inspection_flow test_pipeline test_portal test_cell_consensus -q
```

주요 검증 항목은 분리된 열의 통합과 지그재그 번호, 고정 지도의 유지, 분석 API 입력 처리, 챗봇의 분할 한글 스트림·중복 이벤트·실패·취소·세션 소유권입니다. `test_chat_service`는 외부 통신 대역을 사용하므로 실제 모델 연결 및 배포 주소에서의 응답 완료는 별도로 확인해야 합니다.
